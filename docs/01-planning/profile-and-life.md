## 3. 프로필 — 스탯창의 원칙

게임처럼 보이되 **숫자는 전부 실제 기록에서 나온다.** 스스로 매긴 점수는 없다(질문지 C-3, 숙련도 표시 안 함).

1. **모든 숫자에 출처가 있다.** 능력치 · 레벨 · 업적이 무엇을 세서 나왔는지 누르면 보인다. "보안 72" 같은 느낌 점수는 쓰지 않는다.
2. **Vault 가 자라면 캐릭터도 자란다.** 새 노트 · 프로젝트 · 자격증을 추가하면 다음 배포에서 레벨과 능력치가 저절로 바뀐다 (요구사항 7 "새 노트 자동 반영"과 같은 원리).
3. **게임 용어 옆에 평범한 말을 둔다.** 게임 용어를 앞에 크게, 평범한 말을 작은 부제로 둔다 (예: 크게 "퀘스트 로그", 작게 "경력 · 학력"). 처음 온 사람도 무엇인지 안다.
4. **접근성은 그대로 지킨다.** 방사형 그래프에는 같은 숫자의 표를 함께 두고, 움직임은 움직임 줄이기 설정을 따른다 (KWCAG 점검 결과를 깨지 않는다).

### 3.1 게임 요소의 강도 — **확실하게** (2026-09-28 결정)

채용 담당자에게는 별도 PDF 가 간다(고객 답). 그래서 이 페이지는 이력서 역할을 덜어도 되고, **사이트의 개성을 보여 주는 쪽**으로 간다. 대신 읽기 · 접근성은 지키는 선을 둔다.

| 한다 | 하지 않는다 |
|---|---|
| 제목 · 숫자 · 배지 · 레벨에 **한글 픽셀 글꼴** (Galmuri, OFL — 구현 때 라이선스 재확인 후 자체 호스팅) | 본문 글까지 픽셀 글꼴 (한글 긴 글은 읽기 어렵다 — 본문은 Pretendard 유지) |
| 게임 HUD 틀: 모서리 괄호 테두리, 우주 톤의 은은한 발광, 칸 나눔 | 소리, 계속 반복되는 움직임 (KWCAG 2.2.2) |
| 게임 용어를 전면에 (클래스 · 칭호 · 레벨 · 능력치 · 업적 · 퀘스트) | 게임 용어만 쓰기 — 부제로 평범한 말을 붙인다 |
| 처음 들어올 때 한 번: 경험치 막대가 차오름, 능력치가 펼쳐짐 | 움직임 줄이기 설정에서도 연출 — 바로 완성된 상태로 보인다 |
| 배지에 희귀도 테두리 (자격증 · 수료증 · 이정표를 색으로 구분 + 글자로도 표시) | 색만으로 구분 (KWCAG 1.4.1) |

### 4.2 레벨 — 누적 경험치

기록이 쌓일수록 오르는 재미 요소다. 산식은 페이지에서 누르면 보인다.

| 쌓이는 것 | 경험치 (안) |
|---|---:|
| 공개 지식 노트 1개 | 10 |
| 프로젝트 케이스 1개 | 30 |
| 포트폴리오 프로젝트 1개 | 100 |
| 자격증 · 수료증 1개 | 150 |
| 경력 1개월 | 20 |

레벨은 경험치 곡선(예: 레벨 n 까지 필요한 경험치 = 100 × n^1.5)으로 정한다. 숫자는 구현 때 실제 값으로 맞춰 **지금 기준 20~30 레벨** 정도에서 시작하도록 조정한다. 만렙이 너무 빨리 오거나 영영 안 오지 않게 하려는 것이다.

### 4.4 스킬 — 기술 스택 (자동)

`관련 기술:` 에서 뽑은 141개에는 도구(React)와 개념(분류·평가)이 섞여 있다. 그래서 **한 번 정해 두는 분류표**를 둔다.

- 파일: `pipeline/skills.mjs` — 항목마다 `분야 · 보여 줄지(도구만) · 표시 이름 · 아이콘`
- 새 기술이 `관련 기술:` 에 나타났는데 분류표에 없으면 **빌드가 경고**한다 (메타데이터 검사와 같은 방식). 표에 한 줄 추가하면 끝난다.
- 표시: 분야별 배지, 배지마다 "프로젝트 n개". 누르면 그 기술을 쓴 프로젝트 목록.
- 경로형 표기(`01 Knowledge DB/…/Docker`)는 끝 이름으로 정리한다.

### 4.5 업적 · 자격증 — 배지 진열장

Reddit 트로피 진열장처럼 둥근 배지를 격자로 늘어놓는다. 누르면 상세(발급 기관 · 날짜 · 확인 링크)가 열린다.

| 종류 | 예 | 출처 |
|---|---|---|
| 자격증 | 정보처리기사 | `Profile.md` |
| 수료증 | NVIDIA DLI 과정들 | `Profile.md` (목록을 받아야 함 — §8) |
| 이정표 (자동) | 지식 노트 100 · 500개, 첫 회사 프로젝트, 오픈소스 패키지 배포, 웹 접근성 자체 점검 | 자동 조건 |

- 증서 이미지는 쓰지 않고 **배지 그림 + 확인 링크**로 한다. 수료증의 개인정보(생년월일 · 번호)를 다룰 일이 없어진다. NVIDIA 는 Credly 같은 공개 확인 링크가 있으면 그것을 건다.
- 배지 그림은 사이트에서 직접 그린다 (분류별 색 · 모양). 발급 기관 로고는 상표라 쓰지 않는다.

### 4.5.1 칭호 도감

업적 하나에 칭호 하나. 달성하면 칭호를 얻고, 그중 하나를 **장착**해 이름 위에 단다 (`Profile.md` 의 `title:`). 도감에는 모든 칭호가 나열된다.

- **얻은 칭호** — 칭호 · 업적 · 얻은 날짜
- **못 얻은 칭호도 보인다** — 어둡게, 조건과 진행도 막대 (예: 567 / 1000). 사이트가 자라며 하나씩 풀린다
- 희귀도는 테두리 색 **과 글자**로 함께 표시한다 (KWCAG 1.4.1)
- **자동 업적**은 Vault 에서 센다. **기록 업적**(자격증 · 수료증)은 `Profile.md` 에 적으면 얻는다. 수료증은 주제별로 묶어 업적이 된다
- 얻은 날짜: 자동 업적은 조건을 넘긴 노트의 작성일, 기록 업적은 발행일

**희귀도 기준 — 들인 노력과 드문 정도**

|---|---|
| 일반 | 시작하면 얻는 것. 첫 한 번, 하루 분량 |
| 희귀 | 같은 일을 여러 번. 몇 주 분량 |

## 5. 프로필 — Vault 에서 관리하는 방식

`03 Portfolio/Profile.md` 한 파일 (2026-09-28 작성). 머리말(YAML)에 정해진 칸, 본문은 `## 자기소개` · `## 사이드 퀘스트` 절. 파일 맨 위 `%% … %%` 주석에 작성 안내가 있고, 주석은 사이트에 나가지 않는다.

| 칸 | 내용 |
|---|---|
| `name` · `name_en` · `class` · `tagline` | 김희섭 · Heesub Kim · 풀스택 엔지니어 · 한 줄 소개 |
| 장착 칭호 | 본문 `## 칭호 장착` 의 체크박스 — 계열별 소제목, 계열 안은 일반 → 전설 순. 하나만 체크. 사이트에는 싣지 않는다 (2026-09-29, 머리말 `title` 에서 옮김) |
| `avatar` | 프로필 이미지 경로. 비면 임시 이미지 |
| `links` | email · github · linkedin |
| `career` · `education` · `training` | `from` / `to` (2024-08 모양, 진행 중이면 비우거나 '현재') + 기관 · 직무/전공/과정명 |
| `certs` | `name` · `name_alt`(다른 언어 이름) · `issuer` · `date` · `kind`(license / course) · `url`(하나 또는 목록) |
| `featured` | 대표 프로젝트 — 포트폴리오 주소의 끝 이름 |
| `traits` | 핵심 역량 — `name` · `desc` · `projects` |

- 파이프라인 `pipeline/src/profile.mjs` 가 읽어 `out/profile.json` 을 만든다. 공개 규칙 · 콘텐츠 가드는 다른 문서와 같이 거치고, 그래프 · 검색 · 트리에는 들어가지 않는다 (`config.mjs` 의 `PROFILE`).
- **형식이 틀리면 빌드가 멈추고 어느 칸이 틀렸는지 알린다** — 날짜 모양, 주소 모양, 자격 종류, 포트폴리오에 없는 이름, 끝이 시작보다 앞선 기간.
- 지금 `/about` 을 만드는 `Portfolio.md` 의 `## 소개` · `## 핵심 역량` 은 **A-4 에서 새 화면으로 바꿀 때 지운다.** 그 전에 지우면 `/about` 이 빈다. 그때까지 핵심 역량이 두 곳에 있다.

## 6. 사진 기록 (`/life`)

> **2026-09-30 구현 (L1)** — 실제 동작은 작업 일지 [2026-09-30 §7](../03-worklog/2026-09-30.md). 아래 설계에서 바뀐 것: 글마다 페이지(`/life/<날짜 또는 slug>`) · 태그, 분류 폴더(`06 Life/<분류>/`), 전시 → 전시·공연, 지도(`map` · 한국 지도 그림)는 **빼고** `address` 에 넣은 지도 앱 링크로 "지도에서 보기" (고객 결정), 얼굴 흐림 전까지 `consent: true` 만 공개.

지금은 올릴 사진이 없으므로 **틀만 설계하고 구현은 사진이 생길 때 한다.**

### 6.1 형태

- 인스타그램형: 한 편 = 사진 여러 장 + 짧은 글. 목록은 정사각 격자, 누르면 크게 보기(좌우 넘기기 · 키보드 · 스와이프).
- 분류 6개: 여행 · 음식 · 카페 · 일상 · 전시·공연 · 운동. (2026-09-30 전시 → 전시·공연. 노트에는 `전시`·`공연` 만 적어도 된다)
- 지식 그래프 · 전체 검색 · 사이드 트리와 **분리**. 헤더 메뉴와 프로필의 "사이드 퀘스트"에서만 들어간다.

### 6.2 Vault 구조

| 무엇 | 어디 |
|---|---|
| 글 (한 편 = 노트 하나) | 새 폴더 `06 Life/` — 예: `06 Life/2026-10 제주.md` |
| 사진 | `05 Attachments/Life/` — Obsidian 첨부 설정이 이미 `05 Attachments` 라 끌어다 놓으면 그 아래로 간다 |

```yaml
---
date: 2026-10-03
category: 여행
place: 제주 · 성산
map: [33.46, 126.93]    # 지도에 찍을 지역 좌표 (가게 단위가 아니라 동네 단위)
---
![[IMG_0001.jpg|성산일출봉 앞 바다]]
![[IMG_0002.jpg|해녀의 집 전복죽]]
짧은 글…
```

`|` 뒤의 글이 사진 설명(대체 텍스트)이다. 비어 있으면 제가 초안을 채워 드리고 확인받는다 (질문지 G-6).

### 6.3 사진 처리 (빌드 시)

1. **위치 정보 삭제** — 사진 파일 안 GPS 좌표 · 기기 정보를 전부 지운다. 지도 위치는 사진이 아니라 머리말의 `map` 에서만 온다.
2. **크기 변환** — 화면 폭별 2~3벌, WebP/AVIF. 원본 3~10MB → 수백 KB.
3. **얼굴** — 머리말에 `consent: true` 가 없는 사진은 얼굴을 찾아 흐리게 한다. 자동 탐지는 놓칠 수 있으므로 **처음 올리는 글은 흐린 결과를 확인받는다.**
4. **지도** — 외부 지도 서비스를 불러오지 않고, 빌드 때 **우주 톤의 한국 지도 그림**에 지역 점을 찍는다. 외부 요청이 없어 보안 헤더(CSP)를 바꿀 필요가 없고, 방문자 정보가 지도 회사로 가지 않는다.

### 6.3.1 구현 (A-3, 2026-09-28)

`pipeline/src/media.mjs` — `processImage(Vault 경로, 쓰임새)` 하나로 프로필 · 사진 기록이 같이 쓴다.

| 단계 | 내용 |
|---|---|
| 공개 범위 | Vault `05 Attachments` 아래만. 밖을 가리키거나 `..` 로 빠져나가면 빌드가 멈춘다 |
| 형식 | JPEG · PNG · WebP · AVIF · GIF · TIFF. **HEIC 는 처리하지 못한다** (sharp 기본 빌드에 HEVC 해석기가 없음) — iPhone 은 "높은 호환성" 으로 찍거나 JPEG 로 내보내야 한다. 빌드가 그렇게 안내한다 |
| 방향 | 폰 사진은 픽셀을 눕혀 두고 방향 표시만 붙인다. 메타데이터를 지우면 표시도 사라지므로 먼저 실제로 돌린다 |
| 크기 | 쓰임새별 폭 — avatar 160/320/640(정사각, 얼굴 쪽으로 자름), photo 480/960/1600, thumb 240/480. 원본보다 키우지 않는다. WebP |
| 메타데이터 | 전부 삭제 (GPS · 기기 · 시각). 결과 파일을 다시 열어 남은 게 있으면 빌드를 멈춘다 |
| 이름 · 캐시 | `web/public/media/<내용 해시>-<폭>.webp`. 내용이 바뀌면 이름이 바뀌어 1년 캐시(`_headers`). 안 쓰게 된 파일은 빌드가 지운다 |
| 목록 | `out/media.json` — 화면이 `srcset` 을 만든다 |

- 시험 `npm run test:media` — GPS · 기기 정보 · 방향 6 을 넣은 시험 사진으로 26개 항목. 처리 코드에 일부러 메타데이터를 남기는 버그를 넣으면 실패하는 것까지 확인했다.
- 프로필 이미지가 비어 있으면 `web/public/avatar-placeholder.svg` (고리 달린 행성) 를 쓴다.
- sharp 는 0.35.5 — 0.34 는 libvips 취약점이 알려져 있었다.

### 6.4 사진이 계속 쌓일 때 — 보관 방식 (그때 결정)

| 방식 | 장점 | 단점 |
|---|---|---|
| A. Vault git 에 그대로 | 지금 흐름 그대로 (커밋하면 반영) | 사진이 쌓이면 저장소가 GB 단위로 무거워지고 빌드가 느려진다 |
| B. Git LFS | 저장소 본체는 가볍다 | GitHub 무료 용량 · 전송량(월 1GB)이 빌드마다 소모된다 |
| C. 원본은 Cloudflare R2, 변환본만 사이트로 | 용량 걱정 없음 (10GB 무료, 전송료 없음) | 사진을 올리는 단계가 하나 늘어난다 (Obsidian 플러그인 또는 명령 하나) |

처음 몇십 장은 A 로 시작하고, **저장소가 500MB 를 넘기 전에 C 로 옮기는 것**을 권한다. 옮기는 시점은 빌드가 크기를 재서 알려 준다.
