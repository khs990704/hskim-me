## 4. 전체 목록 가독성
- 같은 높이의 묶음 142개가 이어지던 것을 분야(9) → 하위 분류(처음엔 접힘) → 카드로. 반복되는 앞부분(`Knowledge DB /`, `Project Index /`) 제거, MOC · 소개 · 포트폴리오는 머리말 링크
- 지식 노트는 제목 카드(설명 없음, 태그 있으면 셋). 프로젝트 케이스는 케이스 단위 카드 — 대표 문서(폴더 바로 밑, 같은 폴더를 가장 많이 링크하는 문서) 제목 · 설명 2줄 + 나머지 문서 링크 줄. 큰 케이스(secuai 등)는 상자 안에 안쪽 폴더마다 카드
- 찾기 칸(제목 · 설명 · 태그) — 그려진 목록을 숨기고 보이기만 한다(데이터를 다시 싣지 않음). 문서 한 편씩 센다
- 접힌 묶음 안 링크도 모두 HTML 에 남긴다 (크롤러 진입점, D-09)
- 찾을 때 스크롤이 튀던 원인 셋: 거르기가 그린 뒤에 돌았다(→ useLayoutEffect), 칩 줄이 사라질 때 브라우저 scroll anchoring, 입력할 때 html scroll-padding-top 만큼 당김 → 이 페이지만 끔
- 묶음 · 모바일 분야 칩 줄을 부드럽게 여닫기. 모바일 찾기 칸 너비 고정
- QA 에 전체 목록 검사 추가 (처음 접힘, 링크 수, 펼치기, 찾는 중 찾기 칸이 움직이지 않음, 지우면 원상태)
- 시험: `npm run qa` 3개 엔진 통과, `qa:html` 600쪽 오류 0

## 6. 사이드 탭 가독성
- 폴더 노트(… MOC · 폴더와 같은 이름 · 하위 케이스를 가진 프로젝트 묶음)를 그 폴더 맨 위로 올린다 (gen-static). 폴더 이름을 노트 링크로 합쳐 보았으나 여닫기가 화살표로만 되어 불편해 되돌림
- 폴더 줄 전체로 여닫기. 폴더 · 문서 · 구역 모두 같은 글씨 크기 · 색, 구분은 화살표와 들여쓰기(단계마다 16px + 세로 기준선)
- 지금 문서는 강조 막대 · 강조색, 그 경로 폴더는 굵게. Knowledge DB 분야에 그래프 색 점. 긴 제목은 두 줄까지
- 트리 폭은 1440px 이상만 320px, 그보다 좁으면 256px — 노트북에서 본문 폭(694 · 678px)을 지키려고
- 시험: `npm run qa` 3개 엔진 통과, `qa:html` 600쪽 오류 0
