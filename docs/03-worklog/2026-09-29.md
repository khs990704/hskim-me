## 2. 칭호 장착을 Obsidian 에서

머리말 `title:` 에 이름을 직접 적던 것을, `Profile.md` 맨 아래 `## 칭호 장착` 의 체크박스로 바꿨다.

- 목록은 칭호 표(`pipeline/achievements.mjs`)에서 뽑아 넣었다 — 계열별 소제목, 계열 안은 일반 → 희귀 → 영웅 → 전설 (높은 등급이 아래)
- `profile.mjs` 가 체크된 하나를 장착 칭호로 읽고, 이 절은 사이트에 싣지 않는다
- 시험: 체크 없음 → 칭호 없음, 얻은 칭호 → 장착, 못 얻은 칭호 → 빌드 멈춤, 두 개 → 빌드 멈춤
- 한계: Obsidian 목록에는 획득 여부를 표시할 수 없다 (파이프라인은 Vault 를 쓰지 않는다). 획득 여부는 사이트 칭호 도감에서 본다
- 칭호를 새로 추가하면 빌드가 "목록에 없는 칭호" 를 경고한다

긴 섹션을 처음에는 일부만 보이고 "전체 보기 (n개 더)" 로 펼친다 (`web/components/profile/ShowMore.tsx`, `aria-expanded`).

| 섹션 | 접힌 상태 |
|---|---|
| 칭호 도감 | 12개 (넓은 화면 2줄) — 필터 · 계열을 적용한 결과에서 |

- 3개 엔진에서 펼치기 · 접기 · 키보드(Enter) · 필터와 함께 쓰기 확인

## 4. 화면 시험 도구를 저장소로 (`web/scripts/qa/`)

임시 폴더에 두던 시험 도구가 세션마다 지워져 매번 다시 만들었다. 저장소에 넣었다 (고객 조건: 토큰 · 속도 최소화).

| 명령 | 하는 일 | 시간 |
|---|---|---|
| `npm run qa` | 빌드 결과를 `_headers` 그대로 서빙 → Chromium · Firefox · WebKit **동시에** 11쪽(데스크톱 7 · 모바일 4) + 키보드 + 스탯창 | 약 45초 (차례로 돌면 2분) |
| `npm run qa:html` | W3C 검사기로 전체 쪽 문법. 검사기는 처음 한 번 `~/.cache/hskim-qa` 에 받음 | 약 16초 |

- 통과하면 엔진마다 한 줄, 실패만 자세히. 개발 서버가 켜져 있어 다른 곳에 빌드했으면 `QA_ROOT=경로`
- 시험할 페이지는 파일 이름이 아니라 특징(수식 · 도표 · 코드가 있는 쪽)으로 고른다 — 노트가 바뀌어도 따라간다
- 일부러 망가뜨린 빌드로 실패를 잡는지 확인. 1차는 기다리던 요소가 없으면 도구가 멈춰 버려, 단계마다 오류를 잡아 "시험 중단" 으로 보고하게 고침
- `playwright` 를 web 개발 의존성에 추가 (브라우저 엔진은 설치 때 받지 않는다 — `~/.cache/ms-playwright` 에 이미 있음)
