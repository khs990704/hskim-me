## 한 일

### 1. Next.js 사이트 구축
- `web/` 에 Next.js 15 App Router + 정적 export + Tailwind v4 구성
- 페이지 — 노트 `/notes/[...slug]`, 프로젝트 `/projects/[...slug]`, `/portfolio`, `/index-all`, 홈(임시)
- 탐색 — Vault 폴더 트리, 목차(스크롤 추적), 백링크 패널, 위키링크 호버 미리보기
- 본문 — 수식(KaTeX), 표(가로 스크롤), 코드, 다이어그램(P1 구현 이식)
- SEO — 페이지별 title·description·canonical·OG, `sitemap.xml`, `robots.txt`
- 다크/라이트 테마, 모바일 서랍

### 2. 성능 — 사이드 트리 분리
- 서버 렌더 시 477개 항목이 **모든 페이지 HTML 에 박혀 페이지당 103KB**
- `/tree.json` 으로 분리해 한 번만 받도록 전환
- **페이지 103KB → 22KB(gzip 5.3KB), 전체 108MB → 37MB**

### 3. 본문 타이포그래피 (고객 요청)
- 제목 계층을 색으로 구분 — h1 흰색 / h2 시안+좌측막대 / h3 보라 / h4 이하 흐린 회색+자간
- 강조 표현 — 굵게 호박, 기울임 청록, 인라인 코드 분홍, 취소선 흐림
- 글머리 기호·인용문·체크박스 목록 정리, 라이트 테마용 색 별도 지정
- **색만으로 의미를 전달하지 않도록** 크기·굵기·막대를 함께 사용

### 4. 다이어그램 (고객 지적)
- P1 에서 JS 만 이식하고 **CSS 를 빠뜨려** 본문과 구분되지 않던 문제
- 머리말(라벨·조작 힌트·도구) + 격자 배경을 가진 `figure` 로 재구성
- 테마 전환 시 예전 색으로 남던 버그 수정 — 원본 소스를 `data-src` 에 보관 후 재렌더

### 5. 고객 검수 반영 6건
| 지적 | 원인 | 조치 |
|---|---|---|
| 미리보기 시 다이어그램이 코드로 복귀 | 미리보기 상태가 본문 컴포넌트 안에 있어 리렌더마다 주입 HTML 복원 | 미리보기를 별도 컴포넌트로 분리, 본문은 무상태화 |
| 위키링크 클릭 시 깜빡임 | 주입된 `<a>` 가 전체 페이지 재로드 | 클릭을 가로채 Next 라우터로 전달 |
| 사이드 트리가 폴더 여닫을 때마다 튕김 | 스크롤 조건에 펼침 상태가 포함 | 이동 직후 1회만 동작하도록 변경 |
| 스크롤 판정이 느슨함 | 화면 안에 걸치기만 하면 유지 | 가운데 25~75% 밖이면 끌어오도록 |
| 전체 목록에서 트리가 펼쳐진 채 유지 | — | 문서가 아닌 화면에서는 전부 접음 |
| 좁은 화면 서랍이 헤더에 갇힘 | **헤더의 `backdrop-blur` 가 `fixed` 자식의 기준 박스가 됨** | 서랍을 포털로 `body` 에 렌더 |
| 미리보기 깜빡임 | `mouseout` 이 링크 내부 요소 간 이동에도 발생 | 링크 바깥으로 나갈 때만 닫도록 |

### 6. 라우트 버그와 방어
- **`/projects` 404** — `Project Index/Project Index.md` 가 폴더 노트 + 컨테이너 폴더 규칙에 두 번 걸려 라우트가 `projects` 로 축약됐으나 해당 페이지가 없었음
- `/notes`, `/projects` 구역 대문 페이지 추가 (해당 문서가 있으면 문서, 없으면 목록)
- **빌드 후 라우트 검증 추가** (`web/scripts/verify-routes.mjs`) — 모든 문서에 페이지가 있는지 대조, 없으면 빌드 실패

### 7. Project Index 비공개 전환
- 고객 문의로 필요성 검토 → **삭제 불가 판정**. `04 Operations/Project 케이스 지식화 규칙` 11번이 갱신을 요구하고, 공개 문서 3건과 운영 문서 3건이 참조
- 다만 **`포트폴리오 상태` 열이 내부 진행 상태**라 공개 부적합 (Vault `AGENTS.md` 기준과도 충돌)
- `pipeline/exclude.txt` 에 등록 — 파일은 유지, 공개만 제외. 공개 문서 477 → 476개
- 사이드 트리에도 같은 컨테이너 폴더 규칙 적용 — `DROP_SEGMENTS` 를 파이프라인 설정에서 가져다 쓰도록 통일
