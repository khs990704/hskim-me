## 2. 방문 통계 (P7-6)

**결정** — Cloudflare Web Analytics. 쿠키 · 동의 창 없음, 가벼움, 이미 쓰는 Cloudflare 안. Google Analytics 는 광고 · 판매 · 가입이 없는 사이트에 비용(쿠키 동의, 속도, CSP 완화, 차단기 누락)만 커서 쓰지 않는다. 필요해지면 추가.

**발견** — Web Analytics 에 hskim.me 가 이미 "Automatic setup" 으로 등록돼 있었다 (도메인 연결 때 자동 생성으로 보임, 고객은 켠 적 없음). Cloudflare 가 응답에 `static.cloudflareinsights.com/beacon.min.js` 를 끼워 넣는데 CSP `script-src` 가 막아 집계 0, 모든 페이지 콘솔에 CSP 위반이 찍히고 있었다 (Playwright 로 확인).

**조치** — `_headers` CSP 에 두 곳만 추가: `script-src https://static.cloudflareinsights.com`, `connect-src https://cloudflareinsights.com`. 자동 설정은 hskim.me 응답에만 끼워 넣으므로 테스트 주소 방문은 섞이지 않는다.

**확인 (배포 뒤)** — Chromium · Firefox · WebKit 모두 `beacon.min.js` 200, CSP 위반 0. 방문 보고는 같은 주소의 `POST /cdn-cgi/rum` → 204. 자동 설정은 보고를 같은 출처로 보내 `connect-src cloudflareinsights.com` 은 실제로 쓰이지 않지만, 수동 스니펫으로 바꿀 때를 위해 둔다.

Cloudflare 무료 요금제의 zone 트래픽은 국내 통신사에서 해외 거점으로 가는 경우가 많다고 알려져 있다. 9/23 측정(FCP 0.4s)은 도메인을 Cloudflare zone 으로 옮기기(D-13, 9/27) 전이라 드러나지 않았다. 해결 방향은 고객과 정한다.

**해결 — D-17** (고객 결정: 프록시 끄기)
1. 문서 확인 — Pages 문제 해결 문서의 DNS Only 안내, CAA 없음
2. 방문 통계를 직접 삽입으로 (`layout.tsx`, `location.hostname === 'hskim.me'` 일 때만). Web Analytics 는 "Enable with JS Snippet installation". 처음 넣을 때 셸 인용 때문에 따옴표가 빠졌는데, 호스트별 실행 시험으로 잡아 고쳤다
3. 고객이 `hskim.me` CNAME 을 DNS only 로 (`www` 는 Proxied 유지)
4. 확인 — A 레코드 172.66.x (Pages), `cf-ray … ICN`, 첫 응답 0.08s. `www` · `http` → `https://hskim.me` 301, 보안 헤더 · robots · 사이트맵 · 네이버 태그 · 404 정상, `pages.dev` 만 noindex. 방문 보고가 이제 `cloudflareinsights.com/cdn-cgi/rum` 으로 간다 (204) — 9/29 에 남겨 둔 `connect-src` 가 쓰인다. 세 엔진 CSP 위반 0
