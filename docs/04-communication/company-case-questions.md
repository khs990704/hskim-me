- 각 질문 아래 `답:` 옆에 적어 주세요. 짧게 쓰셔도 됩니다.
- **모르면 `모름`이라고 쓰시면 됩니다.** 모르는 항목은 그 케이스를 가장 보수적인 형태로 재작성합니다.
- `성격` 칸은 노트를 보고 추정한 것입니다. 틀렸으면 고쳐 주세요.
- 기준과 판정 방식은 [회사 케이스 공개 검수](company-case-review.md)에 있습니다.

## 1. Hazard Data — 데이터 구축 사업

> 데이터셋은 AI Hub에 공개돼 있고, 코드는 개인 GitHub 두 곳에 올라가 있습니다.  
> `building_hazard_data_codes`, `processing_sdf_file`

성격 (추정이 틀렸으면 수정):

**1-1. 회사가 이 사업의 수행기관(주관 또는 참여)이었나요, 하도급이었나요?**

답: 주관

**1-2. 개인 GitHub에 코드를 올린 것을 회사가 알고 있거나 허락했나요?**  
이미 공개된 상태라 가장 중요한 질문입니다.

답: 이건 내가 작업 할때 썻던 코드로 회사랑은 완전한 연관이 있지는 않아. 다른 화학물 데이터를 수집할때도 쓸 수 있는 공통화된 것만 코드를 올렸고 현재 그건 private repo야.

답: 아니

답: 그랬었는데, 지금은 서버 자체를 내렸는지 접속이 안되는거 같아.

## 3. NSR — 용역 (가장 조심해야 할 건)

> 발주처와 과업 내용 자체가 민감할 수 있습니다.  
> 셋 다 모르면 발주처 이름을 빼고 "공공기관 정책 문서 RAG 챗봇" 정도로 일반화합니다.

성격 (추정이 틀렸으면 수정):

**3-1. NSR이 국가보안기술연구소가 맞나요? 맞다면 발주처 이름을 밝혀도 되나요?**

답: 맞아.

**3-2. 용역에 참여할 때 보안서약을 했나요?**

답: 비슷했는데 나는 챗봇만 만들기 위해 참여한 부분이라 잘 모르겠네. 중간에 임시로 참여했어. 시작부터 참여한 인력이 아니야.

**3-3. "사이버안보 정책 DB에 RAG 챗봇을 붙이는 일"이라는 과업 내용이 입찰 공고처럼 외부에 공개된 정보인가요?**

답: 이건 NSR 내부에서만 접근 가능한 사이트에서 사용가능한 챗봇으로 알고 있어. 그냥 외부 공개 사이트는 아니야.

## 4. On-device Security — 연구과제

> OP-TEE 보안 저장소, C ONNX 패키징, Rust 추론·버퍼 소거가 여기에 속합니다.

성격 (추정이 틀렸으면 수정):

**4-1. ETRI 주관 과제가 맞나요? 과제명이나 과제번호를 알 수 있나요?**

답: 맞아. 과제명은 `On-device AI 정보 유출 방지를 위한 AI 구현 정보 은닉 기술 개발` 이고 과제 번호는 `RS-2025-02215590`이야.

**4-2. 보안과제로 지정됐나요?**  
확인 방법: 과제 참여 때 쓴 보안서약서 / 협약서·과제계획서 첫 장의 보안등급 표시 / IRIS(iris.go.kr) 참여과제 조회 / 회사 연구관리 담당자에게 문의

답: 그건 모르겠어. 지금 확인할 수 있는 IRIS에 로그인은 했는데, 어디서 확인하는지를 몰라.

**4-3. 이 결과로 특허 출원이나 논문이 예정돼 있거나 진행 중인가요?**  
출원 전에 내용을 공개하면 신규성을 잃을 수 있어서, 보안과제 여부만큼 중요합니다.

답: 우리는 ETRI가 메인으로 진행하는 것과는 달라서 아마 논문은 나중에 따로 우리 회사에서 할 수 도 있어.
